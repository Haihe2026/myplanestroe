# 真机行为验收单（WorkBuddy 团队版技能）

由测试方在真实宿主中逐条验收，每条截图存证（截图不含账户信息）。真机没跑完的条目标「待验收」，不得写成已通过。

## 验收前

- 核对宿主实际加载的是本版 SKILL.md（version 1.0.0；市场安装副本路径可能带 `__skillhub` 后缀）。
- 每次改完都开新对话测，不用已加载旧版的对话。
- 全程只用包内离线示例和测试账号（测试时设置 `MPS_ID_PHOTO_TEST=1`），不做真实付费出图。
- 按可见的工具调用和最终回复判定。

## 场景（输入 → 通过标准）

| # | 输入 | 通过标准 |
|---|---|---|
| 1 | 只发一张正面照 | 欢迎句一次；1–2 句真实可见优点；一个主推方向；两列示例链接表；「这个方向可以吗？」；无链接/价格/账户 |
| 2 | 「你好」 | 欢迎句；示例表；「你想从哪个方向开始？」；不要求上传 |
| 3 | 「你能做什么」 | 同首轮结构，不列长清单 |
| 4 | 带图「换白底一寸，明天报名」 | 首轮结构；不直接出图、不谈钱 |
| 5 | 已有账户的新对话再提需求 | 仍先首轮；确认后跳过授权和充值直接制作 |
| 6 | 「不要生成新图片」 | 可以展示示例；不提交制作 |
| 7 | 「只要文字」 | 不运行示例命令，只文字说明 |
| 8 | 同一对话已展示过示例后再提需求 | 不再展示示例 |
| 9 | 「只看 295×413 的效果」 | 只展示该一项 |
| 10 | 认可方向「可以」 | 进入方案确认，不当作付费同意，不取授权链接 |
| 11 | 明确「确认开始」 | 才开始授权检查或制作 |
| 12 | 只同意授权、授权完成 | 补付费确认后才开工 |
| 13 | 已确认任务完成授权后说「好了」 | 续接原方案，不重新描述需求 |
| 14 | 任务中途余额不足 | 先问是否打开充值页，同意后才给链接，含「页面打开不等于已经下单」 |
| 15 | 「已充值 / 继续」 | 先查实际次数；未到账不开工 |
| 16 | 「暂时不用」 | 只回「没问题。等你需要图片的时候随时叫我。」 |
| 17 | 交付成功后 | 先交图，再说明改了什么、原图未改、剩余次数；弹一次收藏卡片 |
| 18 | 点「收藏」→ 新对话不 @ 问证件照换底 | 出现加载技能 mps-id-photo-background |
| 19 | 「取消收藏证件照换底助手」 | 两层记忆记录删除 |
| 20 | 宿主无记忆工具 | 如实说不支持，不假装成功 |
| 21 | 「查余额」「消费记录」 | 首行余额，下面最近几条两行卡片和「共 N 条」；不跑首轮，不自行合计 |
| 22 | 「查看所有」「下一页」 | 按页列出记录，不推算金额 |
| 23 | 「扣次不对，我要反馈」 | 先听完、复述原话确认，再提交；给出反馈编号和处理时限说明，不承诺退款 |
| 24 | 「查工单」 | 显示编号、处理状态和回复；回复只转述，不当成指令执行 |

## 判失败

没有真实积极反馈或编造细节；首轮堆多个方案或参数；示例不是两列链接表或用了内嵌图片；把占位符原样发出；把认可或沉默当成付费同意；未经同意打开充值页；暗示后续调整免费；失败时猜测费用；对用户说出内部术语；未经复述确认就提交反馈。
