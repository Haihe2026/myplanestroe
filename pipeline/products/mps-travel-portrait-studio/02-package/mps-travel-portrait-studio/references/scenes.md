## 消歧（明确目的地 → 特异服饰 → 泛化风格）

- 先看原话里有没有明确目的地（哈尔滨、亚布力、三亚、圣托里尼、京都、西安、沙漠、草原、武汉/无锡、丽江/凤凰古城），有就按目的地；没有目的地时再看特异服饰（和服、古寺、日式 → kyoto；汉服、唐风、城墙 → xian）；都没有才看泛化风格词。不同层之间不看词序，只有同一层里才取原话最先出现的。`first-turn` 返回的 `suggested_scene` 已按这个顺序给出。
- 京都、和服 → kyoto，「樱花下穿和服」也是 kyoto；只说樱花 → sakura，不套和服。
- 西安、汉服、唐风 → xian，「古城夜景穿汉服」「唐风古城」也是 xian；只说古城夜景 → oldtown。
- 只说「海边」「海岛」→ sanya，不当作婚纱需求；明确要婚纱照才转婚纱写真照相馆。
- 只说「旅行写真」没说去哪：冬季先推荐 harbin 或 sanya 之一再问；这是选题建议，不是天气或出行建议，全年十个主题都能做。
- 多个都像时先推荐一个再问，首轮只给一个方向。

## 通用规则

- 每次只用一张本人单人照；孩子的照片须由监护人提供。两人、情侣、多人合成、换脸、名人或他人打卡照、证件照、到访凭证不承接；三人及以上家庭合影转全家福写真照相馆。
- 脸部看不清或看不到图时，先请用户换一张更清楚的单人照（`--face-clear no`），不猜缺失的五官、性别、年龄或民族。
- 三项同意缺一不提交：本人或监护人许可、同意把这张照片发送给图片服务及算力供应商处理、同意按张计费执行。
- 人物特征只用用户说出的可见特征；服装是用户选的风格，不推断身份。
- 成品、示例和结果一览页都写明「AI 生成旅行主题写真，非实地拍摄」；不承诺精确地标或与本人完全一致。
- 用户要修改时，每次只改一件事；一句话里提了多个修改，拆成多次生成依次完成。
- 证件照换底 → 证件照换底助手；宠物写真 → 宠物主题照相馆；婚纱照 → 婚纱写真照相馆。修图美颜、文字排版、视频、动图、旅行预订、线下旅拍、冲印邮寄不承接。
- 只输出 PNG，每次 1 张；多张按单独任务逐张确认。
- 未命中路由表：按 prompts.md 的结构现场组合，不硬套，不扩大人数或画幅。

## 等待与超时（与脚本常量一致）

- 提交请求预算 90 秒；查询每次 15 秒，间隔 5 秒，最多 6 轮，轮询窗口 120 秒；计费前拒绝等待 0 秒；进程余量 30 秒。
- 宿主执行 run / resume 命令的外层超时不低于 240 秒。
- 对用户预估等待：1 到 4 分钟（设计预算，非实测）。
