## Claude 回话原文（修复需求，一字不改）


现状（member-0.10.61-wechat/wechat_binding.py + /auth/wechat/wechat.js）：
- callback() 只把登录状态记为 approved，并给手机返回“请回到刚才的账户页面继续，随后回原 Skill 对话”；
- 真正的关联（register_product、试用领取、quick-entry/status 变为 registered）只在 finish() 里做，而 finish() 只由电脑端页面每 3.5 秒轮询触发；
- 关联入口 pending 从 Skill 签发起 300 秒过期，finish() 时过期就 401“原技能入口已过期”。
后果：用户关掉电脑页、在手机上打开、或操作超过 5 分钟，关联都不会完成，也不会跳付费页。

需要修改：
1. 在 callback() 里，微信换取身份成功后，立即在服务端完成与 finish() 相同的关联动作（注册、试用领取、绑定微信身份、标记 used）。finish() 改为幂等：已完成就只发会话并返回付费页地址。这样关掉电脑页面也不影响关联。
2. callback 返回给手机的页面文案改为：关联已完成时写“关联完成。电脑上的页面会自动进入付费页面；也可以直接回到原 Skill 对话说『继续』。”。如果 callback 和发起扫码的是同一个浏览器（手机直接打开的情况），直接设置会话并跳转到 /membership/<product>/。
3. 关联入口有效期：从用户点“显示微信二维码”（start）起算，或把 pending 有效期延长到 15–30 分钟；start 时校验一次即可，finish/callback 不再因签发满 300 秒而拒绝。
4. 电脑端页面：finish 返回错误（过期、已绑定其他微信等）时显示明确提示，并给出“回到原 Skill 说『继续』获取新链接”。轮询出错时不要静默停止。
5. 验证：用合成账户模拟以下五种情况，都要在 /quick-entry/status 得到 registered —— 电脑页保持打开、扫码后立刻关闭电脑页、手机直接打开链接、签发后第 6 分钟才扫码、同一身份重复扫码。只读核对和测试时不调用真实生图，不动生产订单和余额。
