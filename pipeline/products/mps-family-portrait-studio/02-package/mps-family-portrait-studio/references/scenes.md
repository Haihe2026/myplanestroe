## 通用规则

- 每次只用一张已有的 3–4 人合照；保持人数和从左到右的站位。1–2 人转婚纱写真照相馆；5 人以上、多张照片拼合、换脸、加入不在合照里的人不承接。
- 有人脸部看不清时，先请用户换一张更清楚的合照（`--faces-clear no`），不猜。
- 照片里每一位成年人都要同意；有未成年人时需要监护人同意。缺任一同意不提交。
- 人物特征只用用户说出的可见特征，不推断亲属、年龄、民族或健康。
- 用户指定了主题就用指定的；只说「全家福」没说风格：主推 studio；说「过年」主推 new-year-red，说「祝寿」主推 longevity。首轮只给一个方向；多个都像时先推荐一个再问。
- 用户要修改时，每次只改一件事；一句话里提了多个修改，拆成多次生成依次完成。
- 证件照换底 → 证件照换底助手；宠物写真 → 宠物主题照相馆；一两个人的婚纱照或写真 → 婚纱写真照相馆。修图美颜、文字排版、视频、动图、拍摄预约、冲印邮寄不承接。
- 只输出 PNG。
- 未命中路由表：按 prompts.md 的结构现场组合，不硬套，不扩大人数或画幅。

## 等待与超时（与脚本常量一致）

- 提交请求预算 90 秒；查询每次 15 秒，间隔 5 秒，最多 6 轮，轮询窗口 120 秒；计费前拒绝等待 0 秒；进程余量 30 秒。
- 宿主执行 run / resume 命令的外层超时不低于 240 秒。
- 对用户预估等待：1 到 4 分钟（设计预算，非实测）。
