# 技能付费页模板与展示配置

自 2026-10-25 起，所有新增技能沿用此约定。此处规范展示，不改变既有产品的账户、余额、权益及扣费逻辑。

## 页面结构

模板见 `skill-pay.template.html`。标题、简介、服务名称、价格和权益由当前技能配置生成；不得在一个技能的付费页介绍其他技能、钱包区别或生图次数换算。平台操作指引可提及实际使用平台，例如 WorkBuddy。

主页面依次展示：当前技能名称与价值 → 账户余额或该账户的实际权益 → 配置提供的档位 → 支付方式 → 当前技能的价格及计费亮点 → 操作状态 → 页脚“隐私政策 · 免责声明”。订阅型产品可在“账户余额”区域展示实际有效期及权益，不能凭空改成人民币金额。

数据来源、服务局限、非官方合作、不保证、照片暂未开放等完整说明放到 `/membership/disclaimer/#<当前技能说明>`，不可直接删除。实际未开放的功能不列入主页面当前服务卖点，开关与计费保护继续生效。必要的购买、授权和真实交易状态不能用营销文案代替。

## 视觉外壳

沿用通用充值页的飞机站点标识、深绿色渐变、品牌图标栏、支付方式图标、细描边卡片及浅色服务亮点区。外贸获客参考实现为 `../versions/2026-10-25-trade-pay-style/web/trade-leads/`。外壳与支付逻辑分离，技能档位、价格、余额和核款逻辑保留各自实现。

装饰标识与底部服务亮点只能描述当前实际能力；不得把通用页中属于其他技能或指定版本的评分、安全评测、认证链接复制成当前技能的背书。品牌图标展示不等于合作认证，不增加未经核实的评分、认证或成交承诺。

## 技能展示配置

示例见 `skill-display.example.json`。展示字段只描述本技能：`title`、`description`、`balance_label`、`recharge_note`、`pricing_benefit`、`unlinked_hint`、`payment_methods`、`disclaimer_anchor`。后端计费配置仍是价格和免费次数的权威来源；不要把当前金额或免费次数固化进 HTML、脚本和模板。

例如外贸获客使用既有账户响应中的 `price_list.search/company/contact`、`daily_free_trial`、`tiers`；宠物养护使用既有套餐响应中的 `price_fen`、`duration_days`、`pet_profiles`、功能开关。适配器应依技能原有计费方式格式化展示，不改变原账本、不作跨产品换算。

用户可见文案避免“上游、缓存、token、接口、幂等、API”等技术用语。主页面优先表达价值、使用方式和“只为有效结果付费”等真实计费亮点；不能把服务失败、付款登记或待核款说成完成服务或已经到账。实现参数名可继续使用技术标识，不得向页面原样输出技术错误。

## 验证

检查手机未关联状态；改变合成配置中的价格、免费次数、套餐权益后，页面应随配置变化；服务关闭时不宣传当前不可用的能力；免责声明链接可达且全文保留；验证未影响 Temu 页、付款、鉴权和实际扣费。未来扩展时也把本目录约定列入交付检查。
