# 管理后台刷新与时间口径修复 · 2026-11-05

根因：product-directory.js 在所有页面点击页头刷新时都触发 SkillHub采集，并把渠道状态放进全局页头，导致用户/额度页面看到WorkBuddy旧采集时间。旧“用户管理”列表按账户ID分页排序，即使重新读库也会反复出现同一批早期账户；当前页面数据异步读取没有进入页头刷新完成/失败的统一等待。

修复：渠道采集仅在渠道下载视图主动触发，状态放在该页；账户页不混用渠道快照时间。旧用户管理按最近登记或认证记录倒序分页，未知时间最后，增加独立“首次登记”列。账户查询返回generated_at，账户页显示实际读取时间，保留历史认证时间原值。页头刷新等待当前用户管理/来源旅程/用户与额度读取；失败合并进真实错误状态，避免其他统计成功却误称当前列表成功。未改变用户发生时间、首次互动政策、数值或订单，WorkBuddy真实快照仍为原采集日期，没有伪造实时接入或新快照。

修改：member-0.5.0/ops-web/app.js、ops-2026-10-28-journey/panel.js、product-directory.js、users-directory.js、member-0.10.16/journey/report.py。

验证：8项合成SQLite测试覆盖顺序、稳定分页、只读、搜索、新读取时间与历史认证时间分离；1440/390全页模拟覆盖两个账户视图的刷新请求/等待/失败、渠道采集隔离、历史日期不改、状态位置。生产只读预检与源码字节核验通过；匿名用户接口401，Gemini/Temu配置200；公开四份JS字节匹配。无真实客户凭证、真实付款或供应商调用。未登录真实管理员会话代替用户人工验收。

服务器备份：/var/backups/myplanestore/refresh-scope-1793890676（四源文件、shared.db及journey.db），补充JS备份见unified-hook-receipt.json。恢复源文件后重启skill-monitor即可回滚，不用旧DB覆盖新记录。支付页、账户额度、主域关闭状态不变。首次互动依然只能收到Skill主动上报，不把点击刷新当作用户新互动。
