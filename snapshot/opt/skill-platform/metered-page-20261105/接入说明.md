# 通用按次服务接入（2026-11-05）

统一单价 **¥0.30/次**。每个微信关联账户、每个已登记 Skill 首次免费成功交付 1 次。不是每次扫码都赠送；重新登录、重试、重新关联不重置。余额长期有效。实际消费需要客户端接入下面的任务流程，网页访问或扫码本身不扣费。

## 支付页面与服务登记

入口：https://aistore.zhaopintong.com/membership/listing/?skill=稳定技能ID 。不带 skill 或 skill=listing-optimizer 保留现有 Listing 页面和旧账本、原套餐赠送。新服务按自身名称/简介/服务范围显示，不出现其他技能名称。

当前生产登记的旧服务是 listing-optimizer；其他项目请提供稳定技能 ID、名称、简介、一次服务范围及交付字段，由后台在 services.json 显式登记并重启服务，之后使用同一模板。不能凭 URL 新建收费项目，未登记 ID 返回 404，防止随意换名字重复领取体验。service.example.json 是填写示例，不是已发布收费项目。原有免费技能、生图/视频、Temu、宠物及外贸服务均没有被批量改价。

新登记服务默认充值 ¥39/¥99/¥190，对应 130/330/633 次，最后一档余 ¥0.10 留在余额中；不另送旧 Listing 的赠送次数。新项目无需新增网页，后台核款统一进入“按次服务订单”，按金额对应现有收款码。付款登记不等于确认到账；流水唯一、金额核对继续生效。

## 客户端协议

新服务前缀：`https://aistore.zhaopintong.com/platform-api/metered/v1/<skill_id>`；旧 Listing 仍使用 `/platform-api/listing/v1` 和原有多平台交付结构，不要迁移成新命名空间，否则会分离旧资格。

沿用 MyPlaneStore 共享账户 install_secret（43 位 URL-safe 字符）的 `Authorization: Bearer <install_secret>`，不要自行编造凭证。所有 POST 带 `Content-Type: application/json`、`Idempotency-Key`（16–100 位字母数字或 `_ . : -`）。同一操作重试用原键，内容变化用新键；不得把密钥写进 URL。网页使用 HttpOnly 会话，POST 另带 `X-Membership-Request: 1` 并保留本站 Origin。

1. `GET /pricing`：公开价格、服务名、服务范围、套餐、是否可用。
2. `POST /entry`，`{"accepted":true}`：用本机凭证申请短期关联链接，打开返回 url。页面保留原 Skill 的一次性关联票据，在页面内完成微信扫码。新匿名机器先安全生成并保存在本机的 install_secret；不要让模型每次对话另造一个。
3. `GET /entry/status`，使用同一 Bearer。`pending` 未完成；`recognized` 需确认开通；`ready` 带 account。扫码后的网页会自动 POST /enroll；客户端如得到 recognized，也可在用户已明确同意服务条款后 POST /enroll `{"accepted":true}`，重复调用不补发。
4. `GET /me`：`available_fen`、`reserved_fen`、`trial_state=available|held|used`。未登录 401；未确认服务或未微信绑定 403。GET 不会创建资格。
5. 用户确认开始后 `POST /quotes`：`{"request_id":"同一业务任务的稳定编号，16至100位"}`。返回 id、scope、scope_hash、reserve_fen（免费为0，收费30分）、funding相关字段。一次服务的具体范围必须与后台配置一致。
6. `POST /tasks/reserve`：`{"quote_id":"返回的id","confirmed":true}`。402 表示余额不足，应展示本技能支付链接；409 可能已有免费任务占用或报价已使用；503 表示服务未开放。预占不等于已扣款。
7. 生成完整结果后 `POST /tasks/<id>/complete`：`{"evidence":{"scope_hash":"报价返回值","deliveries":[{"target":{"service":"skill_id"},"content":{"result":"实际完整交付文本"}}]}}`。字段由后台 result_fields 配置；默认只有 result，非空且最长20000字符。必须使用报价给的 target，不要提交 success:true 代替完整结果。
8. `GET /tasks/<id>` 查询原任务；完成重试同键返回原结果，不重复扣费。只有结构核验并保存交付成功后才消耗免费体验/结算30分。免费用完不恢复；不同 Skill 的余额和资格隔离。
9. 结果未知时不自报失败释放；`POST /tasks/<id>/release` 返回409，需要可信后台核实失败后释放。无效或缺失交付不会结算，但已有预占可能保持待核查。默认新服务不包含额外修订；原 Listing 不限修改的规则保留。

订单路由沿用 `/orders` POST `{tier_id,source,channel}`；source 为已登记技能 ID 或 website，channel 为 workbuddy_skill/workbuddy_expert/skillhub/website。GET `/orders/<id>` 查询；POST `/orders/<id>/report` 空对象只是登记付款。前端不接受客户端提交价格或到账金额。

错误体为 `{"error":"错误代码"}`；常见：ACCOUNT_REQUIRED(401)、WECHAT_REQUIRED/LISTING_ACCOUNT_REQUIRED(403)、IDEMPOTENCY_KEY_REQUIRED/INVALID_SCOPE(400)、IDEMPOTENCY_CONFLICT/TRIAL_IN_PROGRESS(409)、余额不足(402)、RATE_LIMITED(429)、LISTING_NOT_OPEN(503)。沿用历史错误代码是兼容实现，给用户展示友好中文即可。一般请求体≤16384字节，complete/revise≤262144；每账户约180请求/分钟。不要使用真实凭证做开发测试。

## 能力边界与验证

这是宿主生成文本的服务记账协议。服务器校验并保存交付结构，不声称能鉴定文本质量或阻止宿主绕过调用自行回答；Skill 必须正确接入，不能把免费计数当作宿主模型的不可绕过闸门。供应商 Key 不进 Skill、前端和响应。首次对话统计继续走原 telemetry，不由付款接口猜测。
